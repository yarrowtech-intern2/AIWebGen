# Decision Log

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-11-12 | Next.js + TypeScript for the builder app | One codebase for the UI and the API; official TypeScript SDKs for both the Claude Agent SDK and the Anthropic API |
| D2 | 2026-11-12 | Generated-site framework chosen per project through **site kits** (Static, React to start) | Users can choose a framework; new frameworks are added as kit modules |
| D3 | 2026-11-12 | Provider switch: `claude-code` (local login, testing) and `anthropic-api` (production) | No API key needed during development; production runs under proper API terms |
| D4 | 2026-11-12 | Claude edits a virtual file system through custom tools; no real disk or shell access | Safety; identical behaviour across both providers; minimal edits per turn |
| D5 | 2026-11-12 | Prisma + SQLite for development, Postgres-ready | No setup needed for development; switching later is a one-line change |
| D6 | 2026-11-12 | Email + password auth (Auth.js Credentials + bcrypt) | User preference; no third-party sign-in providers |
| D7 | 2026-11-12 | ZIP export only in the MVP; deploy in phase 2 | Keeps the MVP free of external deploy tokens |
| D8 | 2026-11-12 | Default model `claude-opus-5-5`, adaptive thinking, effort set by env | Most capable default; cost is tuned with effort rather than a smaller model |
| D9 | 2026-11-12 | Server-side refusal fallback (`fallbacks: "default"`) on in `anthropic-api` | If Claude declines a request, the API retries on another model instead of failing; can be turned off |
| D10 | 2026-11-12 | Builder UI: dark + light, follows the system theme, with a toggle | User choice |
| D11 | 2026-11-12 | Static kit uses Tailwind via CDN | No build step for exported static sites; fast, consistent generation |
| D12 | 2026-11-12 | Git: `main` branch, one local commit per milestone, nothing pushed | User choice |
| D13 | 2026-11-12 | First build pass covers M0 + M1, then a check-in | Confirm the local Claude Code login works before building UI |
| D14 | 2026-11-12 | Builder layout: chat on the left, Preview/Code tabs on the right (resizable) | More room for the preview than three columns side by side |
| D15 | 2026-11-12 | Agent file writes go straight to the database (no buffering until the turn ends) | The live preview updates while Claude works; a version snapshot per turn is added in M3 |
| D16 | 2026-11-12 | Until M3, every project belongs to the seeded demo user | Lets the UI ship before accounts |
| D17 | 2026-11-12 | Preview responses carry a CSP `sandbox` and `Access-Control-Allow-Origin: *` | The sandboxed iframe has no origin, so module scripts and `fetch()` need CORS; the CSP keeps generated pages sandboxed even when opened in their own tab. M3 needs a signed preview token, because the iframe sends no cookies |
| D18 | 2026-11-12 | One running turn per project, tracked in memory | Prevents two turns racing on the same files; a multi-server deployment needs a shared store such as Redis |
| D19 | 2026-11-12 | Own session module (bcrypt + `jose` JWT cookie) instead of Auth.js | With email and password only, Auth.js adds little beyond setup risk on Next.js 16 / Cache Components; the module is about 60 lines. Reconsider if social login is added |
| D20 | 2026-11-12 | Preview served under a signed, expiring per-project token (`/preview/<token>/…`) | The sandboxed iframe sends no cookies; relative links keep the token automatically. The builder refreshes it with every file reload |
| D21 | 2026-11-12 | One version per AI turn that changed files, per manual save (repeat saves of the same file within 2 minutes are merged), per restore | Full snapshots are simple and sites are small; restoring creates a new version, so history is never rewritten |
| D22 | 2026-11-12 | Standing requirements: easiest possible UI and flow, mobile-friendly everywhere, GitHub integration | User request |
| D23 | 2026-11-12 | Home page is prompt-first; the first message creates and names the project | Removes the separate "new project" step |
| D24 | 2026-11-12 | Mobile builder shows one view at a time with a bottom tab bar; all views stay mounted | Typing, scroll and the preview survive tab switches |
| D25 | 2026-11-12 | Templates are generated by our own agent from briefs in `scripts/template-briefs.json`, then reviewed | Consistent quality, and it exercises the product |
| D26 | 2026-11-12 | GitHub: a Publish button (reliable path) plus allowlisted GitHub MCP tools for Claude; token now, OAuth later; deploy to GitHub Pages or Vercel | User choice |
| D27 | 2026-11-12 | React preview is built on our server with esbuild (in memory, cached per project); npm packages load from esm.sh through an import map. Replaces the Sandpack plan | Same sandbox and token security as static previews, no third-party bundler iframe, build errors are visible to the server (so the UI can offer "Ask Claude to fix"), and it's testable without a browser. The exported project still uses real Vite |
| D28 | 2026-11-12 | ZIP export adds a README (run instructions) and, for React, a `.gitignore` | The download works on its own |
| D29 | 2026-11-12 | GitHub/Vercel tokens are stored AES-256-GCM encrypted with a key derived (HKDF) from AUTH_SECRET | No extra secret to manage; rotating AUTH_SECRET means users reconnect |
| D30 | 2026-11-12 | GitHub Pages publish: one commit that replaces the repo contents; static sites served from the branch root (`.nojekyll`), React built by a committed GitHub Actions workflow with the right `--base` | Reproducible; the repo always matches the project |
| D31 | 2026-11-12 | Vercel publish uploads files directly through the deployments API (no Git link needed) | Works without GitHub; React projects are built by Vercel with Vite |
| D32 | 2026-11-12 | GitHub MCP for Claude: off by default per project, allowlist of 12 tools (no delete/merge/fork), repository content treated as untrusted data; Messages API MCP connector for `anthropic-api`, HTTP MCP server for `claude-code` | Useful ("import my repo", "open a PR") with a small blast radius |
